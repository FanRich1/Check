# 本地网页工作台

本地前端已接入现有原始文档处理流程。浏览器选择文件后，Python 在本机调用既有解析、模型提取、校验和账单匹配逻辑，结果保存到独立任务。财务及授权变更规则保持既有约束；后续修正了将清关用语误识别为账单修改提示的问题。

## 启动

在项目根目录双击 **`启动账单工作台.cmd`**。浏览器会打开 **http://127.0.0.1:8765**。保留启动窗口；需要停止服务时在窗口按 Ctrl+C。关闭网页标签不会停止任务或删除记录，再次打开地址即可继续查看。

同一端口已有工作台时，双击启动文件会打开已有实例。修改 `.env` 后请先停止旧实例再启动，以读取新配置。端口被其他应用占用时，用下方命令指定其他端口。

如果浏览器没有自动弹出，确认启动窗口显示“工作台已就绪”，再手动打开 http://127.0.0.1:8765 。启动失败会保留窗口并显示错误，错误日志位于 `outputs/web/startup-error.log`。启动文件位于 `Check` 项目文件夹内。

页面提示“无法连接本地工作台”时，先确认服务仍在运行。关闭启动窗口会使前台服务停止；网页即使还开着，也无法继续上传。重新启动后刷新页面，以获取新的会话令牌；重新提交前先查看历史任务，避免对已经收到的请求重复处理。

首次从仓库安装，或更新后提示缺少依赖时：

```powershell
.\.venv\Scripts\uv.exe sync --frozen --link-mode copy
# 或保留现有可选本地 OCR 依赖
.\.venv\Scripts\uv.exe sync --frozen --extra local-ocr --link-mode copy

# 手动启动；可改为 --port 8766
.\.venv\Scripts\python.exe -m shipping_billing.web.server --project-root . --env-file .env --open-browser
```

安装后也可使用 `shipping-billing-web` 命令。运行界面不需要 Node.js，不依赖外部字体或前端 CDN。页面仅监听本机 127.0.0.1，不提供公网访问。

## MySQL 账本

当前本机已启用 MySQL。启动文件会先确保本机数据库可用；右侧新增账本选择和管理入口。首次新建账本并指定记账公司，或将确认正确的旧 state.json 导入新建空账本。以后上传时自动匹配所选账本，不必手动传递上次 JSON。正式账单、任务及备注以数据库为准，任务文件作为证据快照保留。详见 [数据库、迁移与备份说明](database.md)。

首次点击「新建账本」只需填写公司全称；账本名称可留空，系统自动生成。创建后自动选用并返回上传页，已添加的业务材料保留。没有旧账单也能直接开始；「管理当前账本」中的旧账导入为可选操作，选定 JSON 文件后才能导入。已有有效处理记录的账本不能导入覆盖，后续材料直接在工作台上传。

以下手动旧账单上传 / 接续方式仍适用于未配置数据库的文件模式；数据库模式直接选择同一账本处理下一批即可。

## 日常使用

现已提供 [正式人工复审](manual-review.md)：待复核费用点击「查看依据」→「正式复审 / 修正入账」，选择新增、修改、重复或拒绝，校验预览后明确确认。结果页显示正式值，并能直接下载当前有效账本和复审记录。普通核对备注继续独立保留，不自动批准入账。

1. **添加材料**：拖入或选择 EML、PDF、PNG/JPG/TIFF、XLS/XLSX、DOC/DOCX。一次最多 20 个，单文件最多 20 MB，合计最多 60 MB。EML 中的附件会递归读取；DOC 转换仍需要本机 Microsoft Word。
2. **填写记账主体**：填写当前记账公司的完整名称，用于判断 AR/AP。数据库模式下，未选账本时可以输入公司名称，点击「新建账本」会自动带入；选定账本后主体固定为该账本的公司，更换公司请切换或新建账本。未选账本时的输入在刷新和切换账本后保留。文件模式下，第一次可不提供旧账单；已有数据时单独选择旧账单 JSON 数组或完整账本 JSON。
3. **开始处理**：任务在后台依次执行，页面显示当前阶段。离开结果页后也能从历史任务重新打开。每次提交是独立任务；数据库模式继续选择同一账本即可识别历史重复费用，文件模式需要提供旧账本。若已添加材料但尚未选账本，页面会引导选择或新建，材料保留；完成后再次点击「开始处理材料」。
4. **核对结果**：新增、修改、无变化、待复核分别展示；可按操作筛选、搜索费用或交易方。点击「查看依据」查看原始引用、来源位置、已应用的变更及待复核原因。
5. **核对与跟进**：可以标记「已核对」「需补材料」并保存备注。该标记不会自动批准待复核费用，不修改核心账单或账本。
6. **下载或继续**：下载账单结果、可续用账本、字段审计、来源清单或核对备注。点击「接续账本处理下一批」，上传下一批材料，保留旧账单和来源去重信息。示例账本与真实任务分开使用。

页面金额采用后端精确的十进制显示文本，下载保留原始 JSON 数字字节，避免浏览器将大金额舍入。不同币种分别显示，不合并为无依据的跨币种合计。

## 模型与 OCR

文字型 PDF 的费用字段会逐项核对原生文字。仅当各页指定 OCR 已完成、引用可验证且没有识别冲突时，通用的“OCR 仅返回结构化字段 / 未返回原文”提示不再阻止自动入账；金额、编号冲突及付款关系不明仍需处理。扫描件和没有可靠原生证据的材料继续保留复核要求。

图片模式增加了严格的自动核验路径：单页图片的客户和收款说明必须分别有清晰的版面证据，已提取字段引用的文字置信度至少为 0.9，指定 OCR 与本地识别的费用行和单据号必须一致，明确币种下的费用合计必须与原图总额一致。满足全部条件才解除通用图片复核；编号冲突、金额冲突、缺失交易方或低质量关键文字继续阻止入账。背景标志或未使用的 Base 代码识别不佳不会单独否定已核验费用。

本地识别组件可用时默认启用，仍可取消。小于 900 像素宽的图片在启用本地辅助识别时，会生成最多 2 倍放大的临时图交给指定 OCR；原图与本地证据坐标保留。左右地址栏分开提供给模型，付款账号代码不作为客户公司；R.O.E. 作为汇率说明，不能作为数量。

私有原始图片样本已验证两笔应付费用 5.00、21.90 USD，合计 26.90 USD。验证包括真实 OCR 和在线模型识别、真实响应回放的重复处理，以及独立 MySQL 测试账本的网页上传入库。该结果只覆盖此样本与上述条件，不代表所有图片都免复核。核验产物保存在本机 `outputs/image-optimization`，不包含在 Git 提交中。

临时链接建立或下载验证失败时，系统在提交 OCR 前最多再尝试一次；OCR 请求发出后若超时，不会自动重复提交。网络故障会明确提示，不能通过修改公司名称解决。历史任务保留原始快照，新规则用于后续处理；重传时选择同一账本，已入账费用继续执行去重。

在线模型沿用项目 `.env`。页面只显示配置是否存在，不将 API 密钥发送给浏览器。「模型已配置」不代表已完成网络调用。模型服务或网络请求失败时保留失败原因，由用户决定重新处理；不会静默换模型或自动重试整票。

PDF、图片及邮件中的图片使用指定 OCR。勾选「为 PDF / 图片启用指定 OCR」，表示允许为相应页面生成临时下载链接，识别服务可以获取该页面，完成后撤销。优先读取 `tools/cloudflared.exe`，同时兼容旧路径 `outputs/stage2/tunnel/cloudflared.exe`；其他位置可通过启动参数 `--cloudflared 路径` 指定。已有页面 URL 映射时可在「更多选项」上传 OCR 映射 JSON，替代临时链接。临时链接工具与映射二选一。

图片和扫描 PDF 须勾选「为图片 / 扫描件补充本地文字识别」，包括邮件中的图片附件。该选项需要 `local-ocr` 依赖，可用时默认勾选，提供独立标注的文字和位置，不替代指定 OCR，也不取消复核条件。后端按真实文件内容检查图片、扫描页及邮件附件；关闭此选项时会在创建任务和远程调用之前提示启用或安装，避免处理完才发现没有可引用的原文。文字型 PDF 不强制启用。初次安装可使用根目录 `安装运行环境.cmd`。

公司名称比较容忍明确公司后缀（Inc、Ltd、LLC、Corp、Co）末尾句点的有无，例如 `ALL AMERICA FORWARDING, INC` 与原件的 `ALL AMERICA FORWARDING, INC.` 可以匹配。原始名称、账本主体及证据仍保留，自动核对、旧账匹配、导入和人工复审使用同一比较规则。缩写、不同公司后缀、不同拼写仍须显式配置公司别名。

结果页分别列出已识别费用、待复核费用和来源异常（含附件异常）数量。附件自身的失败或未完成状态保留在来源列表和整体任务状态中，正文费用按自身原文证据核对，不再继承附件的阻塞标记。未知币种、付款关系不明和费用本身的证据冲突继续阻止自动入账。历史任务的原始识别文件不会改写，旧页面重新打开也能显示来源与费用的分别统计。

未启用 OCR 的顶层 PDF/图片会在提交前提示配置；邮件中的图片如果无法识别，会在来源清单标为异常，其余成功结果仍保留。既有 OCR 空响应或识别质量问题不会被网页当成成功。可用性取决于指定 OCR 和网络，本前端没有修复历史识别问题。

「更多选项」也可上传 ReconciliationContext JSON，配置明确的公司别名、贷项关系、舍入和合计政策；若与页面主体冲突会拒绝提交。未知字段、无效旧账单、重复编号和不合法 JSON 不会被当作空账本。

## 本地文件

启用数据库后，下表中的 job.json 和 reviews.json 是本地镜像，数据库保存任务及备注的正式记录；result/state.json 是该任务当时的版本。最新有效账本从账本管理导出。

| 位置 | 内容 |
|---|---|
| `data/local/web/<任务编号>/` | 上传材料及必要的 OCR 页面映射 |
| `data/local/web-cache/<任务编号>/` | 对应模型和 OCR 原始归档 |
| `outputs/web/jobs/<任务编号>/job.json` | 任务标题、进度和状态 |
| `outputs/web/jobs/<任务编号>/result/` | 账单、账本、审计、来源及中间结果 |
| `outputs/web/jobs/<任务编号>/reviews.json` | 与核心账本分开的核对标记和备注 |

以上目录均被 Git 忽略。历史记录在重启后仍保留；中断的任务不会自动重复远程调用，会提示重新提交。下载和接续前检查关键结果文件哈希；API 不提供任意磁盘文件读取。页面操作有本地会话令牌、来源检查和文件大小限制。

历史列表展示最近 100 个任务，较早记录仍保留在上述本地目录。
