## 核对后的业务约定

1. 不以“单据号+标准费用名称”作为唯一费用行身份，同名真实费用可多行存在。
2. 通知中的条件费率不是本次已发生费用；合计、已付、余额不另建费用。
3. 提单上的运费预付不表示额外杂费预付，缺金额也不补造运费记录。
4. 邮件发件人不等同账单签发方；托运人、收货人、通知人也不等同账单交易双方。
5. 品牌抬头、收款人和空白账单接收方存在角色不明，保持 null 并复核，不强行挑一个公司。
6. 直接 PDF 文本抽取会丢失列位置：其中一页“已付款”和“已收提单”的 YES/NO 在抽取文本中错配。标签以可见页面对齐为准；这不是已验证的 OCR API 缺陷。
7. MBL 名称附件的可见提单号与邮件 MBL 字段不同。分别保存，不以文件名覆盖正文，也不据此猜测其为更新。
8. 未提供当前记账主体时，保留已知候选并返回复核，不擅自决定 AR/AP。真实基准因此没有强制 CREATE/AP 的标签。
9. 日期分别保存：邮件头、正文落款、装船日、预计到达日与单据日，不能互相填补。
10. 原文没有明确 P/C 列字母的扩展定义；先保留原值。后续可通过显式列词典/样本业务复核启用映射，不能因为 COD 就断定 CC。

## 核对与评测的边界

本文件和本地标签构成可追溯的工作基准，尚不等于业务人员独立确认，也不等于模型评测。独立复核前保留 `independent_human_signoff=false`。修改任何标签必须说明证据、保留版本，并重算受影响的基准检查。
