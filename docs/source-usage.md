# 来源材料用途确认

结果页分别展示费用处理、来源读取异常和材料用途待确认数量。费用已经入账，并不代表附件的读取或用途核对已经结束；运输支持材料没有额外费用，也不等于来源识别失败。

## 当前状态

| 显示 | 含义与操作 |
|---|---|
| 已读取·运输支持材料 | PDF 所有页面原生文字完整，指定 OCR 页面调用完成，原文明示提单 / 运单及运输条款，未发现明确金额或账单标题，且没有提取出的费用。可以展开「用途判断依据」查看原文位置。 |
| 用途待确认 | 当前没有提取出费用，但证据不足以自动判断用途。下载原件核对后确认；不能把 OCR 空返回直接视为无费用。 |
| 已确认·非账单图片 / 已确认·支持材料 | 操作者核对原件后确认无需录入费用，确认人、原因和历史均已保存。 |
| 费用待复核 / 费用已处理 / 费用已复核 | 已提取出费用，依费用处理结果展示，不能通过材料用途确认隐藏费用。 |
| 识别失败，需处理 | 存在文件读取失败、OCR 接口失败、缺少识别配置或页面处理未完成等真实故障，应修复并重新处理，不能通过用途确认改成成功。 |
| 附件仍需处理 | 邮件的附件还有费用复核、用途确认或识别故障；正文费用仍按自身证据处理。 |

自动判断采用保守条件。例如：只有「零条费用」、文件名含 MBL / HBL，或只出现提单号，都不足以判定为支持材料。原文出现明确货币金额、两位小数金额或发票标题时仍保留待确认。不能将提单的发货人 / 收货人直接等同于本次费用的付款人 / 收款人。

## 确认、撤销和导出

1. 在「来源文件与处理情况」中点击图片下方「确认非账单图片」，或其他材料下方「核对材料用途」。
2. 下载并查看原件，选择非账单图片、支持材料或「用途仍待确认 / 撤销原确认」。
3. 填写确认人、具体原因，勾选已核对声明，再点击「确认保存用途」。
4. 通过「查看 / 调整用途确认」可重新核对或撤销。历史逐次追加，旧记录保留，刷新页面后仍可查看。下载列表中的「材料用途确认记录 JSON」导出全部历史。

确认使用文件哈希与记录版本校验，页面过期会要求刷新；重复提交同一请求只返回原回执。保存前原件必须仍存在且哈希一致。下载附件时支持带有 `/part-...` 的来源 ID，并依据归档哈希查找原件。

用途确认只适用于当前任务的当前文件，不是全局忽略规则。相同文件再次上传到新任务，仍依据该任务证据判断。确认不会新增、删除或修改费用，也不会改变正式账本版本；有实际漏识别费用时，应继续识别或重新处理材料。

## 原始记录与存储

原始 `parse.json`、`extraction.json`、`manifest.json`、费用结果和原任务账本均保持原字节。来源区将旧 OCR 提示另列为「原始识别提示」，当前材料用途及费用结果分别展示；来源状态与任务列表根据当前确认结果更新。

数据库模式使用新增的 `billing_source_reviews` 表，首次启动补建，已有账本保留。文件模式保存在任务目录的 `source-reviews.json`。完整备份应包含数据库及原件、任务目录；正式账本 JSON 导出不包含用途确认历史。

.\.venv\Scripts\python.exe -m scripts.database_checks

浏览器验收使用合成邮件、两份含原生文字的运输 PDF、空账单 OCR 的图片及注入模型，在隔离的 SQLite 账本验证原件下载、确认、持久化、撤销、再次确认、导出和手机布局。数据库验收覆盖 SQLite 与独立 MySQL 测试库，不代表真实 OCR 的新增准确率评测。
